Restaurer et migrer●une sauvegarde suffit pour remonter un serveur, ici ou ailleurs.

Restore and migrate●one backup is enough to rebuild a server, here or elsewhere.

Restaurer une app

$ dotbox restore latest --app radarr

Remplace /opt/radarr par sa dernière sauvegarde et relance l'app. Les autres apps ne bougent pas. À la place de latest, une date ou un chemin d'archive précis.

$ sudo dotbox restore latest --app radarr
  ✓ [1/1] Radarr        from 2026-11-22-0400, healthy, old folder kept      24 s

  the old folders, kept: delete them once all is fine (sudo rm -rf ...)
    /opt/radarr.before-restore-2026-11-22-093338

Dot Box montre d'abord les archives choisies et demande une confirmation (-y pour la sauter). Puis il ouvre l'archive à côté, arrête l'app, met son dossier de côté (/opt/radarr.before-restore-<date>, pas effacé), met le nouveau à sa place et relance l'app. Si elle ne repart pas, l'ancien dossier revient à sa place. Les fichiers retrouvent leurs propriétaires et leurs droits. Les autres apps ne bougent pas. Une app arrêtée avec dotbox stop reste arrêtée. À la place de latest, une date (2026-11-21 ou 2026-11-21-0400) ou le chemin d'une archive.

En root: une archive peut contenir n'importe quel fichier de /opt, un compose.override.yml qui monte tout le serveur par exemple. restore passe donc par sudo, sans le service de Dot Box, comme exec, edit et add. Une archive dont un fichier sortirait du dossier de son app est refusée.

Restaurer depuis une destination distante

$ sudo dotbox restore sftp:dotbox-backup@nas.example.com:/backups --app radarr

La plus récente archive de chaque app (ou de celle de --app) est rapportée dans /backups, puis restaurée comme une archive locale. Même chose avec rclone:b2:dotbox-backups. Utile quand le disque du serveur a perdu /backups.

Restaurer tout le serveur

$ sudo dotbox restore latest

Restaure /opt/dotbox, puis chaque app, puis lance sync pour que tout ce qui tourne corresponde à la config restaurée.

Migrer vers un nouveau serveur

  1. Sur l'ancien serveur, une sauvegarde vers une destination que le nouveau peut joindre: dotbox backup --to rclone:b2:dotbox-backups.
  2. Le DNS: change l'enregistrement *.example.com pour l'IP du nouveau serveur. Les certificats ne peuvent être obtenus qu'une fois le DNS pointé vers lui.
  3. Sur le nouveau, installe Dot Box sans lancer init: en root (su -), wget -qO- https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | bash -s -- --no-init.
  1. Restaure: dotbox restore rclone:b2:dotbox-backups --key backup.key. Dot Box relit la config de la sauvegarde, refait l'installation du core avec elle (Docker, Traefik, Authelia, CrowdSec, certificats), puis restaure toutes les apps.
  1. À venir (Journal, 16.7). Restaure: sudo dotbox restore rclone:b2:dotbox-backups --key backup.key. Dot Box installe d'abord Docker, dont rclone a besoin pour aller chercher l'archive, puis relit la config de la sauvegarde, refait l'installation du core avec elle (Traefik, Authelia, CrowdSec, certificats) et restaure toutes les apps. Une archive copiée à la main sur le serveur (scp) s'ouvre aussi, sans passer par rclone.
  1. Les médias: copie /data avec rsync s'ils doivent suivre.

Les apps ajoutées avec dotbox add et celles du Sandbox sont dans la sauvegarde: elles reviennent avec le reste, rien à réinstaller à la main.

Changer de domaine

$ dotbox config set domain example.org
$ dotbox diff
$ dotbox sync

Avant, crée *.example.org vers le serveur (voir Prerequisites). config set ne fait qu'écrire dotbox.yml. diff montre ce qui va changer, sans rien toucher. sync remontre le même plan, demande une confirmation, puis refait tout à partir de dotbox.yml: les certificats, les labels Traefik et la config d'Authelia. Il ne reste à corriger que les adresses que tu as saisies toi-même dans les réglages des apps (notifications, webhooks).

Restore an app

$ dotbox restore latest --app radarr

Replaces /opt/radarr with its latest backup and restarts the app. Other apps are not touched. Instead of latest, a date or a specific archive path.

$ sudo dotbox restore latest --app radarr
  ✓ [1/1] Radarr        from 2026-11-22-0400, healthy, old folder kept      24 s

  the old folders, kept: delete them once all is fine (sudo rm -rf ...)
    /opt/radarr.before-restore-2026-11-22-093338

Dot Box first shows the archives it picked and asks for a confirmation (-y skips it). Then it opens the archive aside, stops the app, moves its folder aside (/opt/radarr.before-restore-<date>, not deleted), puts the new one in place and restarts the app. If it does not come back, the old folder goes back in place. Files get their owners and permissions back. The other apps do not move. An app stopped with dotbox stop stays stopped. Instead of latest, a date (2026-11-21 or 2026-11-21-0400) or the path of an archive.

As root: an archive can hold any file of /opt, a compose.override.yml that mounts the whole server for example. restore therefore goes through sudo, without the Dot Box service, like exec, edit and add. An archive with a file outside its app's folder is refused.

Restore from a remote destination

$ sudo dotbox restore sftp:dotbox-backup@nas.example.com:/backups --app radarr

The latest archive of each app (or of the one given by --app) is brought back into /backups, then restored like a local archive. Same with rclone:b2:dotbox-backups. Useful when the server's disk has lost /backups.

Restore the whole server

$ sudo dotbox restore latest

Restores /opt/dotbox, then every app, then runs sync so everything running matches the restored config.

Migrate to a new server

  1. On the old server, back up to a destination the new one can reach: dotbox backup --to rclone:b2:dotbox-backups.
  2. DNS: change the *.example.com record to the new server's IP. Certificates can only be obtained once DNS points to it.
  3. On the new one, install Dot Box without running init: as root (su -), wget -qO- https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | bash -s -- --no-init.
  1. Restore: dotbox restore rclone:b2:dotbox-backups --key backup.key. Dot Box reads the config from the backup, reinstalls the core with it (Docker, Traefik, Authelia, CrowdSec, certificates), then restores every app.
  1. Coming later (Journal, 16.7). Restore: sudo dotbox restore rclone:b2:dotbox-backups --key backup.key. Dot Box first installs Docker, which rclone needs to fetch the archive, then reads the config from the backup, reinstalls the core with it (Traefik, Authelia, CrowdSec, certificates) and restores every app. An archive copied to the server by hand (scp) opens too, without going through rclone.
  1. Media: copy /data with rsync if it should come along.

Apps added with dotbox add and those from the Sandbox are in the backup: they come back with everything else, nothing to reinstall by hand.

Change the domain

$ dotbox config set domain example.org
$ dotbox diff
$ dotbox sync

First, create *.example.org pointing to the server (see Prerequisites). config set only writes dotbox.yml. diff shows what will change, touching nothing. sync shows the same plan again, asks for a confirmation, then redoes everything from dotbox.yml: the certificates, the Traefik labels and the Authelia config. Only the addresses you typed yourself in app settings (notifications, webhooks) are left to fix.
