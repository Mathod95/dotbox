Ce que fait qBittorrent

  • Radarr et Sonarr lui envoient les torrents qu'ils ont choisis.
  • Il les télécharge dans /data/torrents, depuis les autres pairs, et les partage en retour.
  • Une fois un téléchargement fini, Radarr ou Sonarr le range dans /data/media par hardlink: qBittorrent continue de le partager depuis /data/torrents, sans copie.
  • Son interface web montre les téléchargements en cours. qui en est une autre, plus rapide.

Dans le tag de l'image, 5.3.0 est la version de qBittorrent, v2.1.2 celle de libtorrent, la bibliothèque qui fait le BitTorrent, et ls487 le numéro de reconstruction de linuxserver.

Ce que fait l'installation

  • Elle crée /opt/qbittorrent/config, puis /data, /data/torrents et /data/media, à ton utilisateur, et vérifie que torrents/ et media/ sont sur le même disque.
  • Elle vérifie que le port 56881 est libre sur le serveur, en TCP et en UDP.
  • Elle écrit ses réglages dans qBittorrent.conf avant le premier démarrage (plus bas). L'image de linuxserver ne pose alors pas sa propre configuration par défaut.
  • Elle écrit /opt/qbittorrent/compose.yml, démarre qBittorrent et attend qu'il réponde.

Relancée, l'installation ne refait que ce qui manque. Si un réglage de Dot Box a changé, qBittorrent est d'abord arrêté, parce qu'il réécrit son fichier en s'arrêtant, puis redémarré.

Les réglages que Dot Box ajoute

Dans qBittorrent.conf, chacun vérifié dans le code de qBittorrent 5.3.0. Les autres réglages restent à toi, dans l'interface.

RéglageValeurPourquoi
Session\Port56881Le port des pairs, le seul que Dot Box publie pour une app: les autres pairs s'y connectent pour échanger.
Session\DefaultSavePath/data/torrentsLà où Radarr et Sonarr viennent chercher les fichiers finis.
Session\TempPathEnabledfalsePas de dossier temporaire à part: un fichier ne change pas de place à la fin, le hardlink se fait sur place.

ReverseProxySupportEnabledfalseqBittorrent voit l'adresse de Traefik, dans le réseau dotbox, et non celle de ton navigateur, qui ne serait jamais dans la liste.

Après l'installation

Ouvre son adresse: Authelia te demande de te connecter, puis qBittorrent s'ouvre sans autre mot de passe. Il ne connaît encore ni Radarr, ni Sonarr. Dans Radarr et Sonarr, ajoute-le comme client de téléchargement (Settings, Download Clients): hôte qbittorrent, port 8080, sans nom d'utilisateur ni mot de passe, une catégorie par app (radarr, sonarr).

Si ton hébergeur a un pare-feu devant le serveur, ouvre-y le port 56881 en TCP et UDP: sans lui, qBittorrent télécharge, mais moins vite.

What qBittorrent does

  • Radarr and Sonarr send it the torrents they picked.
  • It downloads them into /data/torrents, from other peers, and shares them back.
  • Once a download is done, Radarr or Sonarr files it into /data/media with a hardlink: qBittorrent keeps sharing it from /data/torrents, with no copy.
  • Its web interface shows the downloads in progress. qui is another one, faster.

In the image tag, 5.3.0 is the qBittorrent version, v2.1.2 the libtorrent one, the library that does the BitTorrent work, and ls487 the linuxserver rebuild number.

What the install does

  • It creates /opt/qbittorrent/config, then /data, /data/torrents and /data/media, owned by your user, and checks that torrents/ and media/ are on the same disk.
  • It checks that port 56881 is free on the server, in TCP and UDP.
  • It writes its settings into qBittorrent.conf before the first start (below). The linuxserver image then does not lay down its own default configuration.
  • It writes /opt/qbittorrent/compose.yml, starts qBittorrent and waits for it to answer.

Run again, the install only does what is missing. If a Dot Box setting changed, qBittorrent is stopped first, because it rewrites its file when it stops, then started again.

The settings Dot Box adds

In qBittorrent.conf, each checked in the qBittorrent 5.3.0 code. The other settings are yours, in the interface.

SettingValueWhy
Session\Port56881The peer port, the only one Dot Box publishes for an app: other peers connect to it to exchange data.
Session\DefaultSavePath/data/torrentsWhere Radarr and Sonarr pick up finished files.
Session\TempPathEnabledfalseNo separate temporary folder: a file does not move at the end, the hardlink is made in place.
PortForwardingEnabledfalseUPnP and NAT-PMP are useless in Docker: the port is already published.
LegalNotice\AcceptedtrueqBittorrent's notice, that you share what you download, accepted so it starts without a terminal.
AuthSubnetWhitelistthe dotbox networkNo password for this network, like Radarr and Sonarr: Authelia already checks who connects from the Internet, and Radarr and Sonarr connect to it with no password.
ReverseProxySupportEnabledfalseqBittorrent sees Traefik's address, in the dotbox network, not your browser's, which would never be in the list.
HostHeaderValidation, ServerDomainstrue, qbittorrent.example.com;qbittorrent;localhostqBittorrent refuses other host names: the app's address, the container name for the other apps, and localhost for its healthcheck.
CSRFProtectiontrueKept, unlike Saltbox: a page from another site cannot drive qBittorrent through your browser.

In the compose: port 56881 published in TCP and UDP, no web port, /data at the same path as on the server (for hardlinks), your user's PUID and PGID, no-new-privileges, and an automatic restart. The CrowdSec bouncer also blocks banned IPs on port 56881.

After the install

Open its address: Authelia asks you to log in, then qBittorrent opens with no other password. It does not know Radarr or Sonarr yet. In Radarr and Sonarr, add it as a download client (Settings, Download Clients): host qbittorrent, port 8080, no username or password, one category per app (radarr, sonarr).

If your host has a firewall in front of the server, open port 56881 there in TCP and UDP: without it, qBittorrent still downloads, but slower.
