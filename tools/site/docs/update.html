Aujourd'hui

Les commandes de mise à jour plus bas sont à venir. En attendant, tout se met à jour avec les commandes d'installation:

QuoiComment
Le binaire dotboxRelance install.sh avec --no-init: il installe la dernière version, sans toucher au reste.
Le core (Traefik, Authelia, CrowdSec)sudo dotbox init relit le catalogue sur GitHub et ne recrée que ce dont la version a changé.
Une appsudo dotbox init d'abord, pour relire le catalogue, puis sudo dotbox install <app>.
 
$ wget -qO- https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | sudo bash -s -- --no-init
$ sudo dotbox init
$ sudo dotbox install radarr

Une app qui demande une version plus récente de Dot Box refuse de s'installer, et le dit: mets d'abord le binaire à jour.

Mettre à jour Dot Box

$ dotbox upgrade

Remplace le binaire et relance l'interface et l'API. Les apps ne sont pas touchées. Si la nouvelle version change le format des manifests ou de dotbox.yml, upgrade convertit les fichiers et l'indique dans son résumé.

$ sudo dotbox upgrade

À venir. Remplace le binaire, sans toucher aux apps ni au core. Si la nouvelle version change le format des manifests ou de dotbox.yml, upgrade convertit les fichiers et l'indique dans son résumé.

Mettre à jour une app

$ dotbox update radarr
$ dotbox update --all

Chaque manifest fixe une version d'image (lscr.io/linuxserver/radarr:5.26.2), jamais latest: ce qui tourne est toujours connu. update passe à la version la plus récente, recrée le container et attend qu'il soit Running avant de passer à l'app suivante. Une app qui ne redémarre pas arrête la série.

$ sudo dotbox update radarr
$ sudo dotbox update --all

À venir. Chaque manifest fixe une version d'image (lscr.io/linuxserver/radarr:7.0.3.10918-ls328), jamais latest: ce qui tourne est toujours connu. update passe à la version la plus récente, recrée le container et attend qu'il soit Running avant de passer à l'app suivante. Une app qui ne redémarre pas arrête la série. Le core se met à jour de la même façon: ses versions sont aussi dans le catalogue.

Les nouvelles versions viennent du catalogue, le dossier catalog/ du repo Mathod95/dotbox: Renovate y propose chaque nouvelle version, la CI la teste, puis elle est fusionnée sur main. Dot Box relit le catalogue à chaque dotbox diff ou dotbox update, sans changer de binaire.
