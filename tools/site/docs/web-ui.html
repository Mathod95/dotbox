JOB

    Where and for whom

    • At https://dotbox.example.com, through Traefik, with its certificate, like an app.
    • Behind Authelia, at two_factor, for the admins group: the interface has no login of its own. Once past Authelia, you are home.
    • The Dot Box service only answers Traefik: it listens on the dotbox network, never on a public address, and refuses a request without the secret header Traefik adds. An app on the network cannot pass itself off as Traefik.

    What you do there

    What the CLI does without sudo, through the same API. Every long action (install, update, back up, apply) is a job of the service, followed live, one at a time, like in the terminal.

    ViewWhat it shows and doesRouteCommand
    OverviewThe core, the apps, the last doctor (run again in one click), the last backup, and the gap with dotbox.ymlGET /status, /doctor, /diffstatus, doctor

    SettingsThe keys of dotbox.yml, checked before writing, then the plan and its confirmation before applying/config, /diff, /syncconfig, diff, sync

    What it does not do

    What would give root to whoever uses it stays in the terminal, with sudo: init, upgrade, restore, authelia, exec, edit and add. A stolen admins account must not be enough to take the server. The interface shows the command to run, without running it.

    Importing your own compose.yml for an app outside the catalog (sudo dotbox add) would be easier from the interface. It is kept for later: a compose file can mount any folder of the server, so it would need guards first.

    How it is made

    • Served by the dotbox binary, the same service as the CLI: nothing else to install, no container, no Node.js, and always the same version as the API.
    • Plain pages: HTML, CSS and a little JavaScript, no framework and no build step (no npm, no Node.js), in the style of this site. The pages call the same JSON API as the CLI (/api/v1): one API for both. It works on a phone too.
    • Live: jobs and logs come through Server-Sent Events, like for the CLI.
    • Nothing is kept in the browser. The state is on the server.
