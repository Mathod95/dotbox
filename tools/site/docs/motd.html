Coded, not yet tried on a server. This page is the specification of dotbox motd (Journal, D86, D89, D90 and step 17). What it never shows is still open (Q55). Debian only for now (D87).

What it is

Each time you open an SSH session, Dot Box prints a short summary of the server: the system, the apps, the core, and what needs your attention. dotbox init installs it by default, and one line in dotbox.yml turns it off.

It is written by Dot Box itself, in the binary, in the spirit of fastfetch: nothing to install, and it shows Dot Box, not only the machine.

What Debian shows today

$ ssh admin@203.0.113.10
Linux dotbox 6.12.117+deb13-amd64 #1 SMP PREEMPT_DYNAMIC Debian 6.12.117-1 (2026-11-12) x86_64

The programs included with the Debian GNU/Linux system are free software;
the exact distribution terms for each program are described in the
individual files in /usr/share/doc/*/copyright.

Debian GNU/Linux comes with ABSOLUTELY NO WARRANTY, to the extent
permitted by applicable law.
Last login: Sat Nov 21 05:09:53 2026 from 203.0.113.20

Dot Box replaces it with its own message, and only its own:

  • The kernel line comes from /etc/update-motd.d/10-uname. Dot Box makes it non-executable.
  • The license text is the static file /etc/motd. Dot Box empties it.
  • The Last login line is printed by sshd itself (PrintLastLog), and Dot Box never changes the SSH configuration on its own: it stays (see What it shows).

Dot Box keeps a copy of what it changes, so turning the MOTD off puts Debian's message back.

How it works on Debian

  • At each SSH login, pam_motd runs the scripts in /etc/update-motd.d/, one after the other, as root. It does not run for su.
  • The login waits for them: a slow MOTD slows down every login. That is why some lines may come from a cache (see Live or cached).
  • Dot Box adds one script there, which runs dotbox motd.

Styles

The command

CommandWhat it does
dotbox motdPrints the message, the same as at login.
dotbox motd --refreshRuns the cached checks again now (doctor, the catalog, CrowdSec) and rewrites their files.
dotbox motd --style <style>Shows another style once (compact, fastfetch or banner), without changing dotbox.yml.Shows another style once (compact, fastfetch, banner or ascii), without changing dotbox.yml.

It goes in the SERVER group of dotbox --help. The settings, as proposed:

# /opt/dotbox/dotbox.yml
motd:
  enabled: true      # false: Debian's message comes back
  style: compact     # compact, fastfetch, banner or ascii (#148)

Live or cached

Some lines cost nothing to compute. Others take seconds, or need the Internet, and would slow down every login.

LineCostWhere it comes from
System, uptime, loadInstant/proc
Memory, disksInstant/proc, the file systems
Core and appsA few tens of millisecondsDocker
CrowdSec bansHundreds of millisecondscscli, in the CrowdSec container
Doctor's problemsSeveral secondsdotbox doctor (DNS, certificates, apt), kept in /opt/dotbox/doctor.json
Apps behind, a new Dot BoxThe InternetThe catalog and the releases on GitHub
Last backupInstantThe backup log (to come, Backup)

The fast lines are computed live at each login: the system, the load, the memory, the disks, the state of the containers. The slow ones are read from files that other jobs write:

  • Doctor runs every night, from a systemd timer, after the 04:00 backup. The MOTD reads /opt/dotbox/doctor.json.
  • The apps behind come from the last dotbox diff or dotbox update.
  • The CrowdSec bans are cached.

Each cached line says how old it is (« 2 h ago »), so old news never looks fresh. dotbox motd --refresh runs the cached checks again now and rewrites their files.

LineCostWhere it comes from
System, uptime, loadInstant/proc

Everything that is not cached is read at each login, without the network. The cached lines come from jobs that run elsewhere:

  • Every night at 05:00, after the 04:00 backup, dotbox-doctor.timer runs dotbox motd --refresh: doctor, the catalog read again from GitHub, the latest release of Dot Box, the pending Debian updates, the CrowdSec bans, and the biggest folder of a disk above 90 %. It may start up to 15 minutes late, so that servers do not all reach GitHub at the same second.
  • The catalog is also read again by dotbox update, so the apps behind follow the last of the two.
  • The Dot Box service counts the CrowdSec bans every 10 minutes.

Each cached line says how old it is (« 2 h ago »), so old news never looks fresh. dotbox motd --refresh runs the cached checks now. A check that fails keeps its last value and its age.

At login, the script gives dotbox motd 5 seconds: a Docker that no longer answers never blocks the connection. As root, dotbox motd works without the Dot Box service. Without sudo, it asks the service.

What it shows

The same lines in all three styles, only the drawing changes. Some lines are always there, the state of the server. Others only show up when something needs you, so the message stays short when all is well. A yellow line says what to run.

The Last login line printed by sshd stays as it is, under the message: Dot Box does not touch the SSH configuration on its own. The SSH hardening option may bring it into the message later.

What it never shows (open, Q55)

Every account that logs in over SSH sees it. Passwords, keys and tokens never appear. The rest is still to discuss: the versions (useful to an attacker who already has an account?), the IP addresses of logins, the names of the apps.

Look and width

  • The colors and symbols of the CLI: ┌ │ └ for the frame, ◇ for a line, ▲ in yellow for what needs you, ■ in red for an error.
