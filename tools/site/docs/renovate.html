Renovate●the bot that keeps the catalog's versions up to date, with no new Dot Box release.

À quoi il sert

Chaque image du catalogue est fixée à une version précise, jamais latest. Quelqu'un doit donc remarquer qu'une nouvelle version est sortie et changer la ligne. C'est le travail de Renovate, une app GitHub hébergée par Mend, installée sur le repo Mathod95/dotbox. Il surveille les registres d'images et les releases, et ouvre une pull request à chaque nouvelle version.

Le catalogue vit dans le repo, et dotbox le lit sur main. Une fois la pull request fusionnée, la nouvelle version est disponible sur tous les serveurs, sans nouveau binaire. Sa configuration est dans renovate.json, à la racine du repo.

La CI du catalogue

Le workflow catalog.yml tourne sur chaque pull request qui touche le catalogue, le code ou les workflows. C'est lui qui autorise une fusion automatique:

  • Le code: cargo fmt --check, clippy et les tests, qui vérifient aussi que chaque manifest est valide.
  • Les images: chacune doit exister dans son registre. Une faute dans un tag fait échouer la CI.
  • Le bouncer: l'archive et le binaire doivent avoir les empreintes écrites dans le manifest.

Les empreintes du bouncer

Le bouncer pare-feu n'a pas d'image: dotbox init télécharge son archive et vérifie deux empreintes, celle de l'archive et celle du binaire qu'elle contient. Renovate ne change que sa version. Le workflow catalog-hashes.yml fait le reste dans la pull request, avec tools/bouncer_hashes.sh:

  • Il déduit de la version l'adresse de l'archive et le chemin du binaire.
  • Il télécharge l'archive et la compare à l'empreinte que GitHub publie pour ce fichier.
  • Il calcule l'empreinte du binaire, écrit les quatre lignes et ajoute un commit dans la pull request.
  • Il relance la CI sur ce commit.

Les messages de commit

Les versions de Dot Box se déduisent des messages de commit: un fix: annonce une version corrective. Une mise à jour du catalogue ne change pas le binaire, Renovate écrit donc chore(catalog):, et chore(deps): pour les crates et les actions. Quand une mise à jour des crates mérite une nouvelle version de Dot Box, c'est une décision à part.

What it is for

Every image in the catalog is pinned to a precise version, never latest. So someone has to notice when a new version is out and change the line. That is the job of Renovate, a GitHub app hosted by Mend, installed on the Mathod95/dotbox repository. It watches image registries and releases, and opens a pull request for each new version.

The catalog lives in the repository, and dotbox reads it from main. Once the pull request is merged, the new version is available on every server, with no new binary. Its configuration is in renovate.json, at the root of the repository.

The catalog CI

The catalog.yml workflow runs on every pull request that touches the catalog, the code or the workflows. It is what allows an automatic merge:

  • The code: cargo fmt --check, clippy and the tests, which also check that every manifest is valid.
  • The images: each must exist in its registry. A typo in a tag fails the CI.
  • The bouncer: the archive and the binary must match the hashes written in the manifest.

The bouncer's hashes

The firewall bouncer has no image: dotbox init downloads its archive and checks two hashes, the archive's and the one of the binary inside it. Renovate only changes its version. The catalog-hashes.yml workflow does the rest in the pull request, with tools/bouncer_hashes.sh:

  • It derives the archive's address and the binary's path from the version.
  • It downloads the archive and compares it with the hash GitHub publishes for that file.
  • It computes the binary's hash, writes the four lines and adds a commit to the pull request.
  • It runs the CI again on that commit.

Commit messages

Dot Box versions are derived from commit messages: a fix: announces a patch release. A catalog update does not change the binary, so Renovate writes chore(catalog):, and chore(deps): for crates and actions. When a crate update deserves a new Dot Box release, that is a separate decision.
