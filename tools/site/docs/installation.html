Un core, puis tes apps

Dot Box s'installe en deux temps. D'abord le core, qui fait tourner tes apps, les rend accessibles et les protège. Ensuite les apps elles-mêmes, que tu choisis dans le catalogue (dotbox list).

Étape 1: lancer le script d'installation

Avant tout, *.example.com doit pointer vers le serveur (voir Prerequisites).

Lance-le en root (su -). C'est la seule fois où root sert: ensuite, tu travailles avec ton utilisateur et sudo.

$ su -
# curl -fsSL https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | bash

Ce que fait install.sh

  1. Vérifie qu'il tourne en root.
  2. Vérifie le système selon les Prerequisites, et s'arrête sans rien modifier s'il ne convient pas.
  3. Installe sudo s'il manque.
  4. Configure ton utilisateur, celui qui fait tourner les apps et Dot Box: demande son nom (par défaut, le compte avec lequel tu t'es connecté), le crée s'il n'existe pas en demandant son mot de passe, et l'ajoute au groupe sudo. Un utilisateur existant garde son mot de passe, son shell et ses clés SSH.
  5. Installe dotbox: télécharge la dernière version, vérifie son checksum SHA-256 et la place dans /usr/local/bin. Un checksum faux arrête l'installation.
  6. Lance dotbox init pour cet utilisateur, sauf avec --no-init (migration, voir Restore & Migration).

Il peut être relancé sans risque: il ne fait que ce qui manque.

init demande le domaine, l'e-mail du certificat et le nom de l'administrateur, dans le terminal ou en options (sudo dotbox init --domain example.com). Ensuite, il:

  1. Vérifie le serveur: ports 80 et 443 libres, espace disque, et *.example.com qui pointe vers le serveur.
  2. Installe Docker s'il est absent, avec la rotation des logs et live-restore, et crée le réseau dotbox.Installe Docker s'il est absent, depuis le dépôt officiel de Docker pour Debian ou pour Ubuntu. Si des paquets en conflit sont présents (docker.io, podman-docker...), il les liste et demande avant de les retirer. Les logs des containers tournent sur quelques fichiers, et les containers continuent de tourner quand Docker redémarre (live-restore). Crée le réseau dotbox.
  3. Prépare l'utilisateur choisi par install.sh: l'ajoute au groupe docker et lui donne /opt et /data.
  4. Démarre Traefik, Authelia, CrowdSec et Dot Box. Traefik obtient un certificat pour chaque sous-domaine.
  5. Programme la sauvegarde quotidienne, en local pour commencer.

init ne met pas à jour le système et ne redémarre jamais le serveur: dotbox doctor signale les mises à jour en attente et quand un redémarrage est nécessaire (voir Post-installation).

Tout est écrit dans /opt/dotbox/dotbox.yml. Les secrets (clés d'Authelia, clé de sauvegarde) vont dans /opt/dotbox/secrets/, lisibles par root seulement.

# /opt/dotbox/dotbox.yml
domain: example.com
email: admin@example.com          # Let's Encrypt
ca: letsencrypt                 # ou zerossl
user: admin                     # fait tourner les apps
admin: admin
paths:
  data: /data
backup:
  schedule: daily 04:00
  keep: 7
  destinations:
    - local: /backups
update:
  schedule: off

sudo dotbox init peut être relancé sans risque: il vérifie, complète ce qui manque et ne recrée rien qui existe déjà.

Étape 3: installer tes apps

$ dotbox install qbittorrent prowlarr radarr sonarr

Chaque app arrive sur son sous-domaine, avec son certificat, déjà branchée aux autres.

Dot Box installs in two stages. First the core, which runs your apps, makes them reachable and protects them. Then the apps themselves, which you pick from the catalog (dotbox list).

Step 1: run the install script

First, *.example.com must point to the server (see Prerequisites).

Run it as root (su -). It is the only time you need root: afterwards, you work with your user and sudo.

$ su -
# curl -fsSL https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | bash

What install.sh does

  1. Checks that it runs as root.
  2. Checks the system against the Prerequisites, and stops without changing anything if it does not match.
  3. Installs sudo if it is missing.
  4. Sets up your user, the one that runs the apps and Dot Box: asks for its name (by default, the account you logged in with), creates it if it does not exist, asking for its password, and adds it to the sudo group. An existing user keeps its password, shell and SSH keys.
  5. Installs dotbox: downloads the latest release, checks its SHA-256 checksum and puts it in /usr/local/bin. A wrong checksum stops the install.
  6. Runs dotbox init for that user, unless --no-init is given (migration, see Restore & Migration).

It can be run again safely: it only does what is missing.

Step 2: answer dotbox init

init asks its questions in the terminal: the domain, the certificate email, the user that will run the apps (by default the one who ran the script) and the admin name. It also takes them as flags: sudo dotbox init --domain example.com. Then it:

init asks for the domain, the certificate email and the admin name, in the terminal or as flags (sudo dotbox init --domain example.com). Then it:

  1. Checks the server: ports 80 and 443 free, disk space, and *.example.com pointing to the server.
  2. Installs Docker if it is missing, with log rotation and live-restore, and creates the dotbox network.Installs Docker if it is missing, from Docker's official repository for Debian or for Ubuntu. If conflicting packages are present (docker.io, podman-docker...), it lists them and asks before removing them. Container logs are rotated over a few files, and containers keep running while Docker restarts (live-restore). Creates the dotbox network.
  3. Prepares the user chosen by install.sh: adds it to the docker group and gives it /opt and /data.
  4. Starts Traefik, Authelia, CrowdSec and Dot Box. Traefik gets a certificate for each subdomain.
  5. Schedules the daily backup, local to begin with.

init does not update the system and never reboots the server: dotbox doctor reports pending updates and when a reboot is needed (see Post-installation).

Everything is written to /opt/dotbox/dotbox.yml. Secrets (Authelia keys, backup key) go to /opt/dotbox/secrets/, readable by root only.

# /opt/dotbox/dotbox.yml
domain: example.com
email: admin@example.com          # Let's Encrypt
ca: letsencrypt                 # or zerossl
user: admin                     # runs the apps
admin: admin
paths:
  data: /data
backup:
  schedule: daily 04:00
  keep: 7
  destinations:
    - local: /backups
update:
  schedule: off

sudo dotbox init can be run again safely: it checks, fills in what is missing and recreates nothing that already exists.

Step 3: install your apps

$ dotbox install qbittorrent prowlarr radarr sonarr

Each app lands on its own subdomain, with its certificate, already connected to the others.
