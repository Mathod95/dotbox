Installation●from a blank server to your first apps, in two commands.

Un core, puis tes apps

Il n'y a pas de type d'installation à choisir. Dot Box installe toujours le même core. Ensuite, c'est toi qui choisis les apps que tu veux, une par une ou plusieurs d'un coup.

ComposantRôleInstallé par
Dockerles containers et le réseau dotboxdotbox init
Traefiksous-domaines et certificatsdotbox init
Autheliaconnexion uniquedotbox init
CrowdSecbloque les attaques sur SSH et sur les appsdotbox init
Dot Boxinterface web et API, sur dotbox.example.comdotbox init
Tes appscelles que tu choisis dans le cataloguedotbox install <app>...

Le core n'installe aucune app de contenu: pas de serveur média ni de client de téléchargement imposés. dotbox list affiche le catalogue.

Étape 1: lancer le script d'installation

Avant tout, *.example.com doit pointer vers le serveur (voir Prerequisites).

$ curl -fsSL https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | sudo bash

Le script télécharge le binaire dotbox pour amd64, vérifie son checksum SHA-256 publié avec la release, l'installe dans /usr/local/bin, puis lance dotbox init. C'est un seul fichier, sans dépendance: ni Python, ni Ansible, ni repo git sur le serveur.

Étape 2: répondre à dotbox init

init pose ses questions dans le terminal: le domaine, l'e-mail du certificat, l'utilisateur qui fera tourner les apps (par défaut celui qui a lancé le script) et le nom de l'administrateur. Il les accepte aussi en options: sudo dotbox init --domain example.com. Ensuite, il:

  1. vérifie le serveur: version LTS, amd64, ports 80 et 443 libres, espace disque, et *.example.com qui pointe vers le serveur;
  2. installe Docker s'il est absent, avec la rotation des logs et live-restore, et crée le réseau dotbox;
  3. prépare l'utilisateur: le crée s'il n'existe pas, sinon l'ajoute au groupe docker sans toucher à son mot de passe, son shell ni ses clés SSH; lui donne /opt et /data;
  4. démarre Traefik, Authelia, CrowdSec et Dot Box; Traefik obtient un certificat pour chaque sous-domaine;
  5. programme la sauvegarde quotidienne, en local pour commencer.

init ne met pas à jour le système et ne redémarre jamais le serveur: dotbox doctor signale les mises à jour en attente et quand un redémarrage est nécessaire (voir Post-installation).

Tout est écrit dans /opt/dotbox/dotbox.yml. Les secrets (clés d'Authelia, clé de sauvegarde) vont dans /opt/dotbox/secrets/, lisibles par root seulement.

# /opt/dotbox/dotbox.yml
domain: example.com
email: admin@example.com          # Let's Encrypt
ca: letsencrypt                 # ou zerossl
user: admin                     # fait tourner les apps
admin: admin
paths:
  data: /data
backup:
  schedule: daily 04:00
  keep: 7
  destinations:
    - local: /backups
update:
  schedule: off

sudo dotbox init peut être relancé sans risque: il vérifie, complète ce qui manque et ne recrée rien qui existe déjà.

Étape 3: installer tes apps

$ dotbox install qbittorrent prowlarr radarr sonarr

Chaque app arrive sur son sous-domaine, avec son certificat, déjà branchée aux autres. Pas de redémarrage du serveur: Dot Box ne touche ni au noyau ni au démarrage du système.

One core, then your apps

There is no install type to choose. Dot Box always installs the same core. Then you pick the apps you want, one by one or several at once.

The core installs no content app: no media server or download client is forced on you. dotbox list shows the catalog.

Step 1: run the install script

First, *.example.com must point to the server (see Prerequisites).

$ curl -fsSL https://github.com/Mathod95/dotbox/releases/latest/download/install.sh | sudo bash

The script downloads the dotbox binary for amd64, checks its SHA-256 checksum published with the release, installs it in /usr/local/bin, then runs dotbox init. It is a single file with no dependencies: no Python, no Ansible, no git repo on the server.

Step 2: answer dotbox init

init asks its questions in the terminal: the domain, the certificate email, the user that will run the apps (by default the one who ran the script) and the admin name. It also takes them as flags: sudo dotbox init --domain example.com. Then it:

  1. checks the server: LTS release, amd64, ports 80 and 443 free, disk space, and *.example.com pointing to the server;
  2. installs Docker if it is missing, with log rotation and live-restore, and creates the dotbox network;
  3. prepares the user: creates it if it does not exist, otherwise adds it to the docker group without touching its password, shell or SSH keys; gives it /opt and /data;
  4. starts Traefik, Authelia, CrowdSec and Dot Box; Traefik gets a certificate for each subdomain;
  5. schedules the daily backup, local to begin with.

init does not update the system and never reboots the server: dotbox doctor reports pending updates and when a reboot is needed (see Post-installation).

Everything is written to /opt/dotbox/dotbox.yml. Secrets (Authelia keys, backup key) go to /opt/dotbox/secrets/, readable by root only.

# /opt/dotbox/dotbox.yml
domain: example.com
email: admin@example.com          # Let's Encrypt
ca: letsencrypt                 # or zerossl
user: admin                     # runs the apps
admin: admin
paths:
  data: /data
backup:
  schedule: daily 04:00
  keep: 7
  destinations:
    - local: /backups
update:
  schedule: off

sudo dotbox init can be run again safely: it checks, fills in what is missing and recreates nothing that already exists.

Step 3: install your apps

$ dotbox install qbittorrent prowlarr radarr sonarr

Each app lands on its own subdomain, with its certificate, already connected to the others. No server reboot: Dot Box touches neither the kernel nor the system boot.
