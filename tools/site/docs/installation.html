Installation●from a blank server to your first apps, in three commands.

Un socle, puis tes apps

Il n'y a pas de type d'installation à choisir. Dot Box installe toujours le même socle, puis les apps que tu demandes, une par une ou par pack.

ComposantRôleInstallé par

Un pack n'est qu'une liste d'apps: tu peux installer le pack downloads puis retirer Sonarr, ou ne prendre que Radarr. dotbox list --packs affiche les packs et leur contenu.

Étape 1: télécharger Dot Box

$ curl -fsSL https://github.com/Mathod95/dotbox/releases/latest/download/dotbox-linux-amd64 \
    -o /usr/local/bin/dotbox
$ chmod +x /usr/local/bin/dotbox
$ dotbox version

Remplace amd64 par arm64 sur un serveur ARM. C'est un seul fichier, sans dépendance: ni Python, ni Ansible.

Étape 2: lancer dotbox init

$ sudo dotbox init --domain mathod.fr --dns-provider cloudflare

init demande ce qui manque (jeton DNS, e-mail pour Let's Encrypt, nom de l'administrateur), puis:

  1. vérifie le serveur: système, ports 80 et 443 libres, espace disque;
  2. installe Docker s'il est absent et crée le réseau dotbox;
  3. crée l'utilisateur dotbox (UID et GID 1000) et les dossiers /opt et /data;
  4. demande le certificat *.mathod.fr;
  5. démarre Traefik, Authelia et Dot Box;
  6. programme la sauvegarde quotidienne, en local pour commencer.

Tout est écrit dans /opt/dotbox/dotbox.yml. Les secrets (jeton DNS, clés d'Authelia, clé de sauvegarde) vont dans /opt/dotbox/secrets/, lisibles par root seulement.

# /opt/dotbox/dotbox.yml
domain: mathod.fr
email: admin@mathod.fr          # Let's Encrypt
dns:
  provider: cloudflare
  token: secret:cloudflare      # /opt/dotbox/secrets/cloudflare
admin: mathod
paths:
  data: /data
backup:
  schedule: daily 04:00
  keep: 7
  destinations:
    - local: /backups
update:
  schedule: off

init peut être relancé sans risque: il vérifie, complète ce qui manque et ne recrée rien qui existe déjà.

Étape 3: installer tes apps

$ dotbox install downloads
$ dotbox install jellyfin seerr

Chaque app arrive sur son sous-domaine, déjà branchée aux autres. Pas de redémarrage du serveur: Dot Box ne touche ni au noyau ni au démarrage du système.

One base, then your apps

There is no install type to choose. Dot Box always installs the same base, then the apps you ask for, one by one or as a pack.

A pack is just a list of apps: you can install the downloads pack and then remove Sonarr, or only take Radarr. dotbox list --packs shows the packs and what they contain.

Step 1: download Dot Box

$ curl -fsSL https://github.com/Mathod95/dotbox/releases/latest/download/dotbox-linux-amd64 \
    -o /usr/local/bin/dotbox
$ chmod +x /usr/local/bin/dotbox
$ dotbox version

Replace amd64 with arm64 on an ARM server. It is a single file with no dependencies: no Python, no Ansible.

Step 2: run dotbox init

$ sudo dotbox init --domain mathod.fr --dns-provider cloudflare

init asks for what is missing (DNS token, Let's Encrypt email, admin name), then:

  1. checks the server: system, ports 80 and 443 free, disk space;
  2. installs Docker if it is missing and creates the dotbox network;
  3. creates the dotbox user (UID and GID 1000) and the /opt and /data folders;
  4. requests the *.mathod.fr certificate;
  5. starts Traefik, Authelia and Dot Box;
  6. schedules the daily backup, local to begin with.

Everything is written to /opt/dotbox/dotbox.yml. Secrets (DNS token, Authelia keys, backup key) go to /opt/dotbox/secrets/, readable by root only.

# /opt/dotbox/dotbox.yml
domain: mathod.fr
email: admin@mathod.fr          # Let's Encrypt
dns:
  provider: cloudflare
  token: secret:cloudflare      # /opt/dotbox/secrets/cloudflare
admin: mathod
paths:
  data: /data
backup:
  schedule: daily 04:00
  keep: 7
  destinations:
    - local: /backups
update:
  schedule: off

init can be run again safely: it checks, fills in what is missing and recreates nothing that already exists.

Step 3: install your apps

$ dotbox install downloads
$ dotbox install jellyfin seerr

Each app lands on its own subdomain, already connected to the others. No server reboot: Dot Box touches neither the kernel nor the system boot.
