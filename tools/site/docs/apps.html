Apps●how Dot Box installs them, and where they come from.

Installer une app

$ sudo dotbox install radarr

Chaque app du catalogue est décrite par un manifest, un petit fichier YAML: son image, son port, son niveau d'accès, ses dossiers. dotbox install en fait une app qui tourne:

  • Un dossier /opt/<app>, avec compose.yml (généré, réécrit à chaque install) et config/ (les réglages et la base de l'app).
  • Le container sur le réseau dotbox, sans port publié: l'app répond sur https://<app>.example.com, par Traefik, derrière Authelia selon son niveau d'accès.
  • Ses fichiers à ton utilisateur (PUID, PGID), jamais à root.
  • Pour les apps de médias, /data au même chemin dans le container et sur le serveur, pour que les hardlinks marchent.
  • Les réglages que Dot Box ajoute dans la configuration de l'app, chacun expliqué sur la page de l'app.
  • L'app notée dans apps: de /opt/dotbox/dotbox.yml, avec son sous-domaine et son niveau d'accès.

Relancé, dotbox install ne refait que ce qui manque. L'app n'est redémarrée que si quelque chose a changé. Les apps installées ne savent rien les unes des autres: les relier (qBittorrent dans Radarr, par exemple) est une étape à part.

Retirer une app

$ sudo dotbox remove radarr
$ sudo dotbox remove radarr --purge

remove arrête l'app et garde sa configuration dans /opt/<app>/config: une nouvelle installation la reprend. --purge efface aussi /opt/<app> et l'image, après une confirmation.

D'où viennent les images

Dot Box prend l'image officielle du projet, quand il en publie une et la maintient. Sinon, celle de linuxserver.io. Toujours à une version précise, jamais latest: une mise à jour est un changement voulu et testé, jamais une surprise au redémarrage.

Installing an app

$ sudo dotbox install radarr

Each app of the catalog is described by a manifest, a small YAML file: its image, its port, its access level, its folders. dotbox install turns it into a running app:

  • A folder /opt/<app>, with compose.yml (generated, rewritten on every install) and config/ (the app's settings and database).
  • The container on the dotbox network, with no published port: the app answers on https://<app>.example.com, through Traefik, behind Authelia according to its access level.
  • Its files owned by your user (PUID, PGID), never by root.
  • For media apps, /data at the same path in the container and on the server, so that hardlinks work.
  • The settings Dot Box adds to the app's configuration, each explained on the app's page.
  • The app recorded in apps: of /opt/dotbox/dotbox.yml, with its subdomain and access level.

Run again, dotbox install only does what is missing. The app is restarted only if something changed. Installed apps know nothing about each other: connecting them (qBittorrent in Radarr, for example) is a separate step.

Removing an app

$ sudo dotbox remove radarr
$ sudo dotbox remove radarr --purge

remove stops the app and keeps its configuration in /opt/<app>/config: a new install picks it up. --purge also deletes /opt/<app> and the image, after a confirmation.

Where the images come from

Dot Box uses the project's official image, when it publishes and maintains one. Otherwise, the linuxserver.io one. Always at a precise version, never latest: an update is a deliberate, tested change, never a surprise on restart.
