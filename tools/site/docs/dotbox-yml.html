Configuration●every setting of dotbox.yml, in one place.

Dot Box keeps its settings in a single file, /opt/dotbox/dotbox.yml. dotbox init writes it with your answers, dotbox install adds each app to it. A setting that is not in the file uses its default value. The file has no comments, apart from its first line: Dot Box may rewrite it whole.

The whole file

Every possible setting, with an example value:

# /opt/dotbox/dotbox.yml
domain: example.com
ca: letsencrypt
user: admin
apps:
  radarr:
    subdomain: radarr
    access: two_factor
  jellyfin:
    subdomain: jellyfin
    access: app
    stopped: true
backup:
  schedule: daily 04:00
  keep: 7
  exclude:
    - "*/cache/*"
  destinations:
    - local: /backups
    - sftp: dotbox-backup@nas.example.com:/backups
    - rclone: b2:dotbox-backups
motd:
  enabled: true
  style: compact

Changing a setting

$ dotbox config get
$ dotbox config set backup.schedule "daily 02:30"
$ dotbox diff
$ dotbox sync
  • dotbox config set checks the key and the value, then only writes the file. Nothing changes on the server yet.
  • dotbox diff shows what would change, dotbox sync shows it again, asks for a confirmation, then applies it.
  • Lists (backup.exclude, backup.destinations) are written by hand in the file, with sudo, then applied with dotbox sync.
  • The web interface does the same in its Settings view. See also config, diff and sync in the CLI.

The apps

One entry per installed app, under apps. dotbox install adds it, dotbox remove takes it out.

KeyDefaultWhat it isChange it
apps.<app>.subdomainthe app's nameThe address of the app: radarr gives radarr.example.com. Lowercase letters, digits and -, never a name Dot Box keeps for itself (auth, dotbox...).config set, then sync.
apps.<app>.accessset by the app's manifestWho gets in: two_factor, app or public (see Accessing Apps).config set, then sync.
apps.<app>.stoppedabsenttrue when you stopped the app with dotbox stop: sync and a reboot leave it stopped.dotbox stop and dotbox start.

The backup

Without a backup section, a daily backup at 04:00 into /backups, 7 kept. All the details: Backup.

KeyDefaultWhat it isChange it
backup.scheduledaily 04:00When it runs: off, hourly, daily HH:MM, or a day and a time (sunday 05:00). A backup missed while the server was off runs at boot.config set, then sync, which rewrites the timer.
backup.keep7How many archives are kept, per app and per destination, from 1 to 365.config set, used from the next backup.

backup.destinations- local: /backupsWhere archives go, one or more: local: a folder of the server (outside /opt and /data), sftp: another machine over SSH, rclone: a remote of /opt/dotbox/secrets/rclone.conf.By hand, then sync.

Secrets

Passwords and keys never go in dotbox.yml. They live in /opt/dotbox/secrets/, readable by root only: the keys of Authelia and CrowdSec, your Authelia password kept for root, the backup key (backup.key), the SSH key of SFTP destinations, and rclone.conf. The whole /opt/dotbox folder is readable by root only: dotbox config get reads the settings without sudo, through the Dot Box service.
