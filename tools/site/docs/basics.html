Qu'est-ce que Dot Box ?

Dot Box est un outil de gestion de serveur, pensé pour héberger et gérer tes contenus sur un serveur Debian ou Ubuntu. Il installe, branche et met à jour les apps que tu choisis (Radarr, Sonarr, qBittorrent, Vaultwarden, ton serveur média...) dans des containers Docker, chacune sur son sous-domaine en HTTPS et derrière une connexion unique.

Tout passe par un seul binaire Rust: l'interface web, l'API et la CLI dotbox. Chaque app est décrite par un petit manifest YAML, que Dot Box transforme en fichier Docker Compose lisible.

Ses deux fonctions principales: récupérer automatiquement tes films et séries, et te permettre de les regarder de n'importe où, sur n'importe quel appareil. Les médias restent sur les disques du serveur.

Dot Box a sa propre interface web, sur dotbox.mathod.fr: catalogue, état des apps, installations et logs en direct. La CLI fait la même chose depuis le terminal, par la même API.

Pourquoi utiliser Dot Box ?

Sous-domaines et HTTPS

Traefik envoie chaque app sur son sous-domaine (radarr.mathod.fr), avec un seul certificat wildcard Let's Encrypt ou ZeroSSL obtenu en DNS-01.

Déploiement rapide

Un serveur qui tourne en quelques minutes: dotbox init ne demande que le domaine, le jeton DNS et une adresse e-mail.

Des apps isolées dans Docker

  • Pas de conflits: chaque app tourne dans son container, avec ses propres dépendances.
  • Un système propre: aucun exécutable ni aucune dépendance des apps n'est installé sur le serveur.
  • Installer et désinstaller en une commande: dotbox install, dotbox remove.
  • Plusieurs instances d'une même app: dotbox install radarr --as radarr-4k ajoute un second Radarr, avec son dossier /opt/radarr-4k, son sous-domaine et son propre câblage.

Une connexion pour tout

Authelia protège chaque app qui n'a pas de vraie connexion, avec double authentification et passkeys, plutôt que de compter sur la connexion de chaque app.

Une app, un fichier compose

Chaque app vit dans /opt/<app> avec son compose.yml. Tes ajustements vont dans compose.override.yml, que Dot Box ne touche jamais. Sans Dot Box, docker compose up -d suffit à la relancer.

Catalogue ouvert

19 apps au départ, et n'importe quel projet qui fournit un fichier compose devient une app avec dotbox add.

Câblage automatique

Installe Radarr après qBittorrent et il est déjà branché: client de téléchargement, catégorie, dossier racine. Prowlarr, Sonarr, Seerr et ton serveur média (Jellyfin ou Plex) suivent la même règle.

Une seule arborescence

Les téléchargements et les bibliothèques partagent /data, sur le même disque: les imports sont des hardlinks, pas des copies.

État voulu, état réel

dotbox diff montre l'écart entre ce que tu veux et ce qui tourne, dotbox sync le corrige.

Sauvegarde et migration

Tout ce qui compte vit dans /opt et les manifests. dotbox backup, puis dotbox restore sur un serveur neuf.

What is Dot Box?

Dot Box is a server management tool, built to host and manage your content on a Debian or Ubuntu server. It installs, wires and updates the apps you choose (Radarr, Sonarr, qBittorrent, Vaultwarden, your media server...) in Docker containers, each on its own HTTPS subdomain and behind a single login.

Everything goes through one Rust binary: the web interface, the API and the dotbox CLI. Each app is described by a small YAML manifest that Dot Box turns into a readable Docker Compose file.

Its two main jobs: fetching your movies and shows automatically, and letting you watch them from anywhere, on any device. Media stays on the server's disks.

Dot Box has its own web interface, on dotbox.mathod.fr: catalog, app states, installs and live logs. The CLI does the same from the terminal, through the same API.

Why use Dot Box?

Subdomains and HTTPS

Traefik sends each app to its own subdomain (radarr.mathod.fr), with a single Let's Encrypt or ZeroSSL wildcard certificate obtained through DNS-01.

Fast deployment

A server running in minutes: dotbox init only asks for the domain, the DNS token and an email address.

Apps isolated in Docker

  • No conflicts: each app runs in its own container, with its own dependencies.
  • A clean system: no app executable or dependency is installed on the server.
  • Install and uninstall in one command: dotbox install, dotbox remove.
  • Several instances of the same app: dotbox install radarr --as radarr-4k adds a second Radarr, with its own /opt/radarr-4k folder, subdomain and wiring.

One login for everything

Authelia protects every app that lacks a proper login, with two-factor authentication and passkeys, rather than relying on each app's own login.

One app, one compose file

Each app lives in /opt/<app> with its compose.yml. Your tweaks go in compose.override.yml, which Dot Box never touches. Without Dot Box, docker compose up -d is enough to restart it.

Open catalog

19 apps to start with, and any project that ships a compose file becomes an app with dotbox add.

Automatic wiring

Install Radarr after qBittorrent and it is already connected: download client, category, root folder. Prowlarr, Sonarr, Seerr and your media server (Jellyfin or Plex) follow the same rule.

One layout

Downloads and libraries share /data, on the same disk: imports are hardlinks, not copies.

Desired state, actual state

dotbox diff shows the gap between what you want and what is running; dotbox sync fixes it.

Backup and migration

Everything that matters lives in /opt and the manifests. dotbox backup, then dotbox restore on a new server.

How does Dot Box work?

Installing an app always follows the same path:

  1. Manifestradarr.yml
  2. EngineRust
  3. compose.yml/opt/radarr
  4. Traefik + Autheliaradarr.mathod.fr
  5. Wiringother apps' APIs
  1. The manifest describes the app: image, volumes, subdomain, SSO and links with other apps.
  2. The engine writes the compose.yml, creates folders and configs before the first start.
  3. Docker Compose starts the container; Traefik routes it to its subdomain, Authelia protects it.
  4. Once the app is Running, the engine connects it to the others through their APIs.
