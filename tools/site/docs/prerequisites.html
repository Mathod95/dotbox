Prerequisites●the server, domain and DNS Dot Box needs.

Le serveur

Dot Box n'a besoin que d'un serveur dédié chez un hébergeur et d'un nom de domaine à toi. Son script d'installation apporte tout le reste.

ÉlémentMinimumConseillé
SystèmeDebian 12 ou 13, installation neuveDebian 13
Processeuramd64, 2 cœurs4 cœurs. Le transcodage par la puce graphique viendra plus tard: Dot Box ne la donne pas encore au serveur média.
Mémoire2 Go pour le core (Traefik, Authelia, CrowdSec, Dot Box)4 Go pour une dizaine d'apps, 8 Go avec un serveur média et une grande bibliothèque
Disque20 Go pour le système et /opt/data sur un disque à part, assez grand pour tes médias
AccèsLe mot de passe root pour l'installation (su -), ou un accès root en SSH si l'hébergeur ne donne que celui-là. Ensuite, ton utilisateur avec sudo.Une clé SSH, sans mot de passe

Réseau

  • Ports 80 et 443 ouverts depuis internet et libres, pour Traefik: le 80 sert à obtenir les certificats et à rediriger vers HTTPS, le 443 aux apps. dotbox init s'arrête si un autre service les occupe.
  • Le port SSH (22 ou le tien), pour l'administration et l'accès de secours.
  • Les ports de certaines apps, seulement si tu les installes: 56881 en TCP et UDP pour les pairs de qBittorrent, 51820 en UDP pour le VPN de wg-easy. Ce ne sont pas des pages web: ils ne passent pas par Traefik.

Si ton hébergeur a un pare-feu devant le serveur, ouvre-y ces ports. Un port 80 fermé chez l'hébergeur est la cause la plus courante d'un certificat qui ne s'obtient pas.

Le domaine

Chaque app est servie sur son sous-domaine (radarr.example.com), jamais par IP et port: les ports des containers restent sur le réseau interne dotbox.

Un sous-domaine d'un domaine que tu utilises déjà convient aussi: avec dotbox.example.com, les apps arrivent sur radarr.dotbox.example.com, et le reste du domaine ne change pas.

Le DNS

Avant de lancer l'installation, fais pointer *.example.com vers le serveur chez ton fournisseur DNS. Tous les sous-domaines arrivent alors sur le serveur, et Traefik envoie chacun vers la bonne app.

NomTypeValeur
*.example.comAL'IPv4 du serveur, par exemple 203.0.113.10
*.example.comAAAAL'IPv6 du serveur, s'il en a une

Dot Box n'a besoin d'aucun accès à ton compte DNS: il ne crée ni ne modifie aucun enregistrement. dotbox init vérifie seulement que *.example.com pointe bien vers le serveur avant d'aller plus loin. Tes enregistrements existants (mail, www...) restent prioritaires sur le wildcard.

Les certificats

Traefik demande un certificat à Let's Encrypt pour chaque sous-domaine, dès que l'app est installée, par le challenge HTTP-01: Let's Encrypt vérifie que le sous-domaine répond sur le port 80 du serveur. Les certificats se renouvellent tout seuls.

Comme tout certificat, ils sont inscrits dans des registres publics: on peut y voir qu'un sous-domaine comme radarr.example.com existe, pas ce qu'il contient.

The server

Dot Box only needs a dedicated server at a hosting provider and a domain name of your own. Its install script brings everything else.

ItemMinimumRecommended
SystemDebian 12 or 13, fresh installDebian 13
CPUamd64, 2 cores4 cores. Transcoding on the GPU will come later: Dot Box does not hand it to the media server yet.
Memory2 GB for the core (Traefik, Authelia, CrowdSec, Dot Box)4 GB for about ten apps, 8 GB with a media server and a large library
Disk20 GB for the system and /opt/data on a separate disk, large enough for your media
AccessThe root password for the install (su -), or root access over SSH if the hosting provider only gives that. Then your user with sudo.An SSH key, no password

A system up to date. A hosting provider's image is often several months old. Before the install, bring it up to date, then reboot if it asks for it:

# apt update && apt full-upgrade
# test -f /var/run/reboot-required && reboot

dotbox init never updates the system and never reboots the server. Afterwards, dotbox doctor reports pending updates and when a reboot is needed.

Network

  • Ports 80 and 443 open to the internet and free, for Traefik: 80 is used to get certificates and to redirect to HTTPS, 443 serves the apps. dotbox init stops if another service uses them.
  • The SSH port (22 or yours), for administration and emergency access.
  • The ports of some apps, only if you install them: 56881 over TCP and UDP for qBittorrent's peers, 51820 over UDP for wg-easy's VPN. They are not web pages: they do not go through Traefik.

If your hosting provider has a firewall in front of the server, open these ports there. Port 80 closed at the provider is the most common reason a certificate cannot be obtained.

The domain

Each app is served on its own subdomain (radarr.example.com), never by IP and port: container ports stay on the internal dotbox network.

A subdomain of a domain you already use works too: with dotbox.example.com, apps land on radarr.dotbox.example.com, and the rest of the domain does not change.

DNS

Before running the install, point *.example.com to the server at your DNS provider. Every subdomain then reaches the server, and Traefik sends each one to the right app.

NameTypeValue
*.example.comAThe server's IPv4, for example 203.0.113.10
*.example.comAAAAThe server's IPv6, if it has one

Dot Box needs no access to your DNS account: it creates and changes no records. dotbox init only checks that *.example.com points to the server before going further. Your existing records (mail, www...) take priority over the wildcard.

Certificates

Traefik requests a certificate from Let's Encrypt for each subdomain, as soon as the app is installed, through the HTTP-01 challenge: Let's Encrypt checks that the subdomain answers on the server's port 80. Certificates renew on their own.

Like any certificate, they are listed in public logs: anyone can see that a subdomain such as radarr.example.com exists, not what it holds.
