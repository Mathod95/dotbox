Your own apps●an app that is in neither the catalog nor the Sandbox, turned into a Dot Box app from its compose file.

Most projects publish a compose.yml. dotbox add reads it and writes a manifest, the same small file the catalog uses. From then on, the app lives like the others: its own subdomain, behind Authelia, on the dotbox network, in /opt/<app>, and in the nightly backup.

Step by step

Say a project gives this compose file:

# compose.yml, as the project publishes it
services:
  notes:
    image: ghcr.io/example/notes:1.4.2
    container_name: notes
    restart: unless-stopped
    ports:
      - "8080:3000"
    environment:
      - NOTES_TITLE=My notes
    volumes:
      - ./data:/app/data

Turn it into an app, and choose its name:

$ sudo dotbox add ./compose.yml --name notes
  read     1 service: notes (ghcr.io/example/notes:1.4.2)
  folder   ./data → data (in /opt/notes)
  ignored  container_name, restart, ports (Dot Box sets them)
  write    /opt/dotbox/apps/notes.yml (subdomain notes, access two_factor, port 3000)
  ready    dotbox install notes

Read the manifest it wrote. This is what will run:

# /opt/dotbox/apps/notes.yml
name: notes
description: "Added with dotbox add (notes)"
min_dotbox: 0.0.6
image: "ghcr.io/example/notes:1.4.2"
port: 3000
access: two_factor
env:
  NOTES_TITLE: "My notes"
  PUID: "{{uid}}"
  PGID: "{{gid}}"
  TZ: "{{tz}}"
volumes:
  - "data:/app/data"

The {{...}} values are filled in at install time. data:/app/data becomes /opt/notes/data on the server. Then install it, like any app:

$ dotbox install notes

The app answers on https://notes.example.com, behind Authelia with two-factor authentication. dotbox install looks in your apps first, then in the catalog.

What add takes from the compose

In the composeWhat add does
imageKept. It must have a pinned version, never latest. Without image (a build: instead), the compose is refused.
environmentKept, as a list or a mapping. PUID, PGID and TZ are added when missing. A value that reads a .env file (${VAR}) is refused: write the value itself.
volumesA folder under /data, with the same path inside the container, stays as it is (hardlinks keep working). Every other folder moves to /opt/<app>/<folder>, named after its last part (./data becomes data). The path inside the container must be absolute.
ports, exposeThe first one gives the web port, the container side (3000 in 8080:3000). Nothing is published: Traefik reaches the app on the dotbox network. No port in the compose: give it with --port.
container_name, restart, networks, labels, hostname, loggingIgnored: Dot Box sets them for every app.
Anything else (command, healthcheck, depends_on...)Refused for now, with the name of the key.
Several servicesRefused: one container per app for now.

The name you give must be free. It cannot be a catalog app (install that one instead), a name Dot Box keeps for itself (authelia, auth...), or an app you already added.

Root only. A compose file can mount any folder of the server, so dotbox add runs with sudo. Installing the app afterwards does not need it.

After the install

  • Address and access. Change the subdomain or the access level in apps: of dotbox.yml, then run dotbox sync, as for any app (Accessing Apps).
  • A new version. Renovate follows the catalog, not your apps. Change image: in /opt/dotbox/apps/<app>.yml (with sudo), then run dotbox update <app>. As for a catalog app, it waits for the app to run and keeps the previous image for dotbox update <app> --rollback. Until then, dotbox diff and the SSH welcome message show that the app runs another version than its manifest.
  • In the list. dotbox list shows your apps next to the catalog, marked "yours".
  • Settings the manifest cannot hold. Write them in /opt/<app>/compose.override.yml with sudo dotbox edit <app>. Dot Box checks the file, restarts the app, and puts the old file back if the app does not start.
  • Backup. Your app is backed up like the others, in its own archive. Its manifest is in /opt/dotbox/apps/, saved with the dotbox archive.
  • Remove. dotbox remove <app> stops it and keeps its config, --purge erases /opt/<app>. The manifest stays in /opt/dotbox/apps/: delete it with sudo to add the app again from a new compose.

Not possible yet

  • Several containers. An app with a database alongside, like Immich, needs an engine that installs several containers. It comes later.
  • Tools without a web page. A command-line tool run now and then (a downloader, a converter) has no web port, and add refuses it.
  • Part of an app without Authelia. The access level applies to the whole subdomain. A path left open for an API, the rest behind Authelia, is not possible.

To share an app that works for you with others, submit it to the Sandbox.
