Post-installation●what Dot Box checks for you, and what is left to do.

Te connecter à Authelia

À faire en premier: tant que ta double authentification n'est pas enregistrée, aucune app derrière Authelia ne s'ouvre. Ton compte existe déjà, au nom de l'utilisateur choisi pendant init, dans le groupe admins.

1. Te connecter

Relis ton mot de passe sur le serveur:

$ sudo dotbox authelia password
  password ••••••••••••••••   (admin, set by dotbox init)

Ouvre https://auth.example.com, ou n'importe quelle app derrière Authelia, puis entre ton nom d'utilisateur et ce mot de passe.

2. Choisir ta double authentification

Authelia ne connaît encore aucun appareil: clique sur « Register device ». Tu arrives dans ses réglages, où tu ajoutes l'une des deux méthodes, ou les deux:

  • Un code à 6 chiffres (One-Time Password), avec une app comme Aegis, 2FAS ou Google Authenticator.
  • Une passkey, gardée par ton téléphone, ton ordinateur ou une clé de sécurité. Un faux site ne peut pas la recopier, contrairement au code.

3. Confirmer que c'est toi

Avant d'enregistrer un appareil, Authelia demande un code de vérification d'identité. Il ne l'envoie pas par e-mail, puisque Dot Box n'en demande aucun: le code est écrit sur le serveur. Lis-le, puis recopie-le dans le navigateur:

$ sudo dotbox authelia verification
  code     X7KQ2M9P   (created 14:02, valid until 14:07)
  note     this is not the 6-digit code: that one comes from the app on your phone

Ce code ne vaut que 5 minutes. Passé ce délai, Authelia refuse l'enregistrement: redemande un code dans le navigateur, puis relance la commande.

4. Terminer

  • Code à 6 chiffres: scanne le QR code avec ton app, puis tape le code qu'elle affiche. Chaque nouvel essai crée une nouvelle clé, garde seulement la dernière dans ton app.
  • Passkey: suis la demande de ton navigateur.

Enregistrer un appareil ne te connecte pas encore: Authelia te demande ensuite un code, ou ta passkey, puis ouvre l'app. Les fois suivantes, c'est le mot de passe puis la double authentification.

Mettre le système à jour

Dot Box ne met pas à jour le système et ne redémarre jamais le serveur: c'est toi qui choisis le moment. doctor signale:

  • les mises à jour en attente, dont celles de sécurité;
  • les mises à jour de sécurité automatiques (unattended-upgrades) si elles sont désactivées;
  • un redémarrage nécessaire, par exemple après une mise à jour du noyau.
$ sudo apt update && sudo apt full-upgrade
$ sudo reboot

Après un redémarrage, Docker relance toutes les apps.

Sécuriser SSH

Dot Box ne modifie jamais la configuration SSH de lui-même: une erreur pourrait te fermer la porte du serveur. doctor signale ce qui manque. Une option de Dot Box pourra l'appliquer pour toi, seulement si tu la lances (à venir). En attendant, c'est dans /etc/ssh/sshd_config:

  • Clés seulement: PasswordAuthentication no.
  • Pas de root: PermitRootLogin no.
  • Garde une session ouverte pendant que tu testes la nouvelle configuration dans une deuxième.

CrowdSec, installé avec le core, bloque déjà les adresses qui enchaînent les tentatives de connexion SSH, sans toucher à cette configuration.

Sortir les sauvegardes du serveur

La sauvegarde quotidienne est active dès init, mais en local: un disque qui lâche l'emporte avec lui. Ajoute une destination distante, voir Backup.

Ton compte existe déjà (Te connecter à Authelia, plus haut). Pour les autres:

Les groupes décident des apps accessibles: family voit le serveur média et Seerr, admins voit tout. Le compte reçoit un lien d'invitation valable 48 heures pour choisir son mot de passe et sa double authentification.

Garder un accès de secours

Si Authelia ou l'interface ne répondent plus: en SSH, dotbox --local parle directement au moteur. Note la commande quelque part avant d'en avoir besoin.

Log in to Authelia

Do this first: until your two-factor method is registered, no app behind Authelia opens. Your account already exists, named after the user chosen during init, in the admins group.

1. Log in

Read your password again on the server:

$ sudo dotbox authelia password
  password ••••••••••••••••   (admin, set by dotbox init)

Open https://auth.example.com, or any app behind Authelia, then enter your user name and this password.

2. Choose your two-factor method

Authelia knows no device yet: click « Register device ». You land in its settings, where you add one of the two methods, or both:

  • A 6-digit code (One-Time Password), with an app such as Aegis, 2FAS or Google Authenticator.
  • A passkey, kept by your phone, your computer or a security key. A fake site cannot copy it, unlike the code.

3. Confirm it is you

Before registering a device, Authelia asks for an identity verification code. It does not email it, since Dot Box asks for no email address: the code is written on the server. Read it, then type it in the browser:

$ sudo dotbox authelia verification
  code     X7KQ2M9P   (created 14:02, valid until 14:07)
  note     this is not the 6-digit code: that one comes from the app on your phone

This code is only valid for 5 minutes. After that, Authelia refuses the registration: ask for a new code in the browser, then run the command again.

4. Finish

  • 6-digit code: scan the QR code with your app, then type the code it shows. Each new attempt creates a new key, keep only the latest one in your app.
  • Passkey: follow your browser's prompt.

Registering a device does not log you in yet: Authelia then asks for a code, or your passkey, and opens the app. From then on, it is the password, then the second factor.

Update the system

Dot Box does not update the system and never reboots the server: you choose when. doctor reports:

  • pending updates, including security ones;
  • automatic security updates (unattended-upgrades) if they are turned off;
  • a required reboot, for example after a kernel update.
$ sudo apt update && sudo apt full-upgrade
$ sudo reboot

After a reboot, Docker starts every app again.

Secure SSH

Dot Box never changes the SSH configuration on its own: a mistake could lock you out of the server. doctor reports what is missing. A Dot Box option will be able to apply it for you, only when you run it (coming later). Until then, it goes in /etc/ssh/sshd_config:

  • Keys only: PasswordAuthentication no.
  • No root: PermitRootLogin no.
  • Keep a session open while you test the new configuration in a second one.

CrowdSec, installed with the core, already blocks addresses that keep trying to log in over SSH, without touching this configuration.

Move backups off the server

The daily backup is on from init, but local: a failing disk takes it with it. Add a remote destination, see Backup.

Create accounts

Your account already exists: init created it in the admins group. Its password can be read again with sudo dotbox authelia password. For the others:

Your account already exists (Log in to Authelia, above). For the others:

$ dotbox user add lea --group family

Groups decide which apps are reachable: family sees the media server and Seerr, admins sees everything. The account gets an invite link, valid for 48 hours, to choose its password and two-factor method.

Watch disk space

Finished downloads that are not imported yet stay in /data/torrents, as do the ones Radarr or Sonarr could not recognize. doctor warns at 85% usage, and Uptime Kuma can send the alert to Discord or by email.

Keep emergency access

If Authelia or the interface stop responding: over SSH, dotbox --local talks to the engine directly. Write the command down before you need it.
