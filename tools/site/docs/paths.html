Les chemins●où vit chaque fichier, sur le serveur et dans les containers.

Paths●where every file lives, on the server and inside containers.

Les règles

  • Deux racines: /opt pour les configs, /data pour les médias et les téléchargements.
  • Les mêmes chemins partout: /data reste /data dans chaque container. Un fichier vu par qBittorrent a le même chemin pour Radarr et pour Jellyfin.
  • Minuscules: les chemins sont sensibles à la casse (movies n'est pas Movies), Dot Box les crée tous en minuscules.
  • Un seul propriétaire: tous les containers tournent avec l'utilisateur dotbox (UID et GID 1000), qui possède /opt et /data.

/opt

/opt
├── dotbox/
│   ├── dotbox.yml            # la config de Dot Box
│   ├── secrets/              # jetons et clés, root seulement
│   ├── apps/                 # tes manifests (dotbox add)
│   └── state.json            # l'état voulu, lu par diff et sync
├── traefik/
├── authelia/
└── radarr/
    ├── compose.yml           # généré par Dot Box, ne pas modifier
    ├── compose.override.yml  # à toi
    └── config/               # monté sur /config dans le container

Garde au moins 20 Go libres sur /opt: les bases de données et les métadonnées de Jellyfin grossissent vite.

/data

/data
├── torrents/
│   ├── movies/               # catégorie radarr
│   ├── tv/                   # catégorie sonarr
│   └── other/
└── media/
    ├── movies/               # Nom du film (2024)/
    ├── tv/                   # Nom de la série/Season 01/
    └── music/

torrents et media sont sur le même système de fichiers: Radarr et Sonarr importent par hardlink, le fichier continue d'être partagé sans prendre deux fois la place.

Un disque à part pour /data: monte tout le disque sur /data, jamais torrents et media sur deux disques différents, sinon chaque import devient une copie.

Changer l'emplacement des données

$ dotbox config set paths.data /mnt/disk1
$ dotbox sync

Seul le chemin sur le serveur change: dans les containers, les données restent sur /data, rien à modifier dans les apps.

The rules

  • Two roots: /opt for configs, /data for media and downloads.
  • Same paths everywhere: /data stays /data in every container. A file seen by qBittorrent has the same path for Radarr and Jellyfin.
  • Lowercase: paths are case sensitive (movies is not Movies), and Dot Box creates them all in lowercase.
  • One owner: every container runs as the dotbox user (UID and GID 1000), which owns /opt and /data.

/opt

/opt
├── dotbox/
│   ├── dotbox.yml            # Dot Box config
│   ├── secrets/              # tokens and keys, root only
│   ├── apps/                 # your manifests (dotbox add)
│   └── state.json            # desired state, read by diff and sync
├── traefik/
├── authelia/
└── radarr/
    ├── compose.yml           # generated by Dot Box, do not edit
    ├── compose.override.yml  # yours
    └── config/               # mounted on /config in the container

Keep at least 20 GB free on /opt: databases and Jellyfin metadata grow fast.

/data

/data
├── torrents/
│   ├── movies/               # radarr category
│   ├── tv/                   # sonarr category
│   └── other/
└── media/
    ├── movies/               # Movie Name (2024)/
    ├── tv/                   # Show Name/Season 01/
    └── music/

torrents and media are on the same filesystem: Radarr and Sonarr import with hardlinks, so the file keeps seeding without taking twice the space.

A separate disk for /data: mount the whole disk on /data, never torrents and media on two different disks, or every import becomes a copy.
